Installation et tests — Monophasé

Une fois le processeur installé, il serait judicieux de vérifier que l’alimentation électrique fonctionne toujours correctement.
Si c’est le cas, nous pouvons exécuter un croquis (programme) pour vérifier si le processeur fonctionne correctement.
Nous allons maintenant tester le bon fonctionnement des autres parties matérielles de la carte-mère.
Cela permettra à la fois de s’assurer que le processeur est opérationnel et de vérifier que les autres composants sont correctement installés et/ou assemblés.
Pour cette prochaine étape, un dispositif de programmation approprié doit être mis en place.

Pré-requis

Pour cette étape, il vous faudra :

  • Un ordinateur (PC ou équivalent) avec un port USB libre. Cet ordinateur peut fonctionner sous Windows, macOS ou Linux.

  • Un programmateur USB vers UART (par exemple, un programmateur FTDI).

  • Un câble USB approprié pour connecter le programmateur à l’ordinateur de programmation.

  • Un câble d’alimentation électrique pour le routeur.

Carte USB vers UART

Un programmateur USB vers UART est nécessaire pour téléverser le croquis (programme) sur le processeur.
Ce programmateur est également utilisé pour surveiller les messages de débogage envoyés par le processeur.
Selon le système d’exploitation (Windows, macOS ou Linux) de l’ordinateur de programmation, il peut être nécessaire d’installer un pilote pour le programmateur.
Les pilotes pour le programmateur FTDI sont disponibles sur le site Web du fabricant.
Les pilotes disponibles sur le site FTDI devraient convenir à la plupart des cas d’utilisation.
Il conviendra de choisir les pilotes de type VCP (Virtual COM Port).

Logiciel de programmation

Pour programmer l’Arduino, vous aurez besoin d’un logiciel de programmation.

La méthode recommandée est Visual Studio Code avec l’extension PlatformIO : elle gère seule le standard C++17 et les bibliothèques du firmware.
L’Arduino IDE reste la méthode la plus simple à prendre en main, au prix de quelques réglages manuels.

Assurez-vous d’installer l’un de ces logiciels avant de continuer avec la programmation de votre carte.

L’Arduino IDE peut être téléchargé à partir du site Arduino.
Pour Windows, veillez à choisir la version Windows et non Windows App.
Si vous êtes totalement débutant dans le domaine de l’Arduino, nous vous recommandons de consulter le tutoriel Découverte de l’Arduino par exemple.
Il y en a beaucoup d’autres disponibles sur Internet.

Mise en place

Remarque

La carte FTDI dispose d’un commutateur ou d’un cavalier pour choisir entre 3,3 V et 5 V. Sa tension doit être celle de l’ATmega328P : sur la carte universelle, 3,3 V (position d’usine du cavalier V sel., voir Configuration des cavaliers) ; 5 V seulement si ce cavalier a été passé en 5 V.

Un programmateur USB vers UART doit être connecté au connecteur FTDI (J0) du PCB.
L’autre extrémité du programmateur doit être connectée à l’ordinateur de programmation (PC ou équivalent) via un câble USB approprié.

La broche à une extrémité du connecteur à 6 voies du programmateur est étiquetée GND. Elle va sur la broche 1 (GND) du connecteur J0, marquée « GND> » sur la sérigraphie du PCB : repérez les deux et alignez-les.

Pour éviter de tordre le connecteur du programmateur, vous pouvez fabriquer un simple câble d’extension.
Seules quatre des lignes sont réellement utilisées (données Tx & Rx, masse et réinitialisation).
Aucune des lignes d’alimentation électrique n’est utilisée par cette carte.

Le fil noir est destiné à la connexion GND (ou 0 V).

Note

La carte FTDI ne peut pas alimenter la carte-mère.

Le routeur doit toujours être alimenté par sa propre source d’alimentation.

Installation du Firmware

Firmware : Mk2_1phase_RFdatalog_temp — PVRouter-1-phase

Site du firmware (en anglais) : fredm67.github.io/PVRouter-1-phase, avec la documentation du code (Doxygen), pour qui veut lire ou modifier le firmware, et l’historique de sa taille et de sa vitesse.

Note

Anciennes cartes, ancien firmware. Cette documentation décrit uniquement le firmware Mk2_1phase_RFdatalog_temp. Le firmware Mk2_fasterControl_Full n’y est plus décrit : même avec une ancienne carte, on installe le nouveau firmware, dont les réglages sont ceux du firmware triphasé, avec les mêmes noms. Le config.h de l’ancien firmware ne convient pas : partez de celui qui est fourni.

  • Carte-mère : mettre PCB_VERSION à PcbVersion::OLD_SEG (carte Mk2 de Robin Emley, afficheur 7 segments) ou PcbVersion::OLD_OLED (seconde ancienne carte, afficheur OLED).

  • Étalonnage : vos valeurs powerCal_grid, powerCal_diverted et f_voltageCal de l’ancien firmware se recopient dans f_powerCalOldBoard, f_powerCalDivertedOldBoard et f_voltageCalOldBoard de calibration.h (lpf_gain et alpha deviennent lpf_gainOldBoard et alphaOldBoard).

  • Sonde CT2 : faire passer par elle les fils de toutes les sorties locales, triacs et relais.

Le détail est dans la section Upgrading from Mk2_fasterControl_Full du journal des modifications du firmware (en anglais).

Avertissement

Le firmware Mk2_1phase_RFdatalog_temp n’a pas encore tourné sur une vraie carte : il passe ses tests natifs, ses vérifications à la compilation et le simulateur de réseau. Sur une installation en service, gardez l’ancien firmware Mk2_fasterControl_Full en attendant.

Étapes communes à toutes les versions : Installation des Logiciels

Bibliothèques pour l’Arduino IDE

Avec l’Arduino IDE, installer ces bibliothèques par le Gestionnaire de bibliothèques (menu : Outils → Gérer les bibliothèques…) :

  • OneWire par Jim Studt et al. (version 2.3.8 ou supérieure)

  • RFM69 par Felix Rusu, LowPowerLab (version 1.5.2 ou supérieure)

  • U8g2 par Oliver Kraus (version 2.36.5 ou supérieure)

  • SPI : incluse avec l’Arduino IDE

Elles sont toutes nécessaires, même sans sonde de température, sans module RF ni afficheur OLED : le code inutilisé est éliminé à la compilation. Avec PlatformIO, tout vient de platformio.ini : rien à installer. Voir le Readme du firmware.

Étape 1 : Téléchargement du Firmware

  1. Ouvrir le navigateur : https://github.com/FredM67/PVRouter-1-phase

  2. Choisir la branche dev dans le menu des branches, au-dessus de la liste des fichiers

  3. Cliquer sur le bouton vert « Code » → « Download ZIP »

  4. Enregistrer le fichier PVRouter-1-phase-dev.zip

  5. Extraire le contenu dans un dossier de votre choix (exemple : Documents/Arduino/)

  6. Le firmware se trouve dans : PVRouter-1-phase-dev/Mk2_1phase_RFdatalog_temp/

Structure du Firmware

Après extraction, vous devriez avoir :

Mk2_1phase_RFdatalog_temp/
├── Mk2_1phase_RFdatalog_temp.ino  (fichier principal)
├── config.h                     (configuration utilisateur)
├── config_system.h              (fréquence du réseau, seuils d’export)
├── config_rf.h                  (liaison radio, si elle est utilisée)
├── calibration.h                (paramètres d’étalonnage)
├── dualtariff.h
├── processing.cpp
├── utils_temp.h
└── ... (autres fichiers)

Important

Les réglages courants sont dans deux fichiers :

  • config.h — Configuration générale (carte-mère, afficheur, sorties, relais, sondes…)

  • calibration.h — Paramètres d’étalonnage (à remplir après l’étalonnage)

config_system.h (fréquence du réseau, export requis, période d’envoi des données, 40 s au plus) et config_rf.h (liaison radio) ne changent que dans des cas particuliers. Le configurateur écrit les trois fichiers config.h, config_system.h et config_rf.h.

Étape 2 : Configuration du Firmware

Astuce

Le configurateur écrit config.h (et, avec le module mk2Wifi, le YAML ESPHome) à partir d’une description de votre installation, en vérifiant vos choix. Il suffit ensuite de remplacer les fichiers et de garder votre calibration.h.

Ouverture du Projet

  1. Lancer Arduino IDE

  2. Menu : Fichier → Ouvrir

  3. Naviguer vers le dossier du firmware

  4. Ouvrir le fichier Mk2_1phase_RFdatalog_temp.ino

  5. Arduino IDE ouvre plusieurs onglets (c’est normal)

Note

Les autres fichiers (.cpp, .h) s’affichent automatiquement dans des onglets séparés.

Configuration dans config.h

Cliquer sur l’onglet `config.h` pour le modifier. Il décrit l’installation avec des réglages, dont voici les principaux ; le détail de chacun est dans le Readme du firmware.

Carte-mère

Selon votre carte-mère :

// Carte Mk2 de Robin Emley, afficheur 7 segments
inline constexpr PcbVersion PCB_VERSION{ PcbVersion::OLD_SEG };

// Seconde ancienne carte monophasée, afficheur OLED
inline constexpr PcbVersion PCB_VERSION{ PcbVersion::OLD_OLED };

// Carte universelle (rév. 6.0 et suivantes)
inline constexpr PcbVersion PCB_VERSION{ PcbVersion::NEW };

Avertissement

Chaque carte a ses entrées analogiques, et la carte universelle utilise la référence interne 1,1 V de l’ATmega328P : un mauvais choix donne des mesures fausses. Après un changement, refaire l’étalonnage.

Le config.h fourni avec le firmware est réglé pour la carte universelle (PcbVersion::NEW).

Format de Sortie Série

Le config.h fourni est en mode IoT, pour le module mk2Wifi. Pour les premiers tests au moniteur série, passer en mode lisible par un humain :

inline constexpr SerialOutputType SERIAL_OUTPUT_TYPE = SerialOutputType::HumanReadable;

Options disponibles :

  • HumanReadable : Affichage facile à lire (recommandé pour débuter)

  • IoT : Format compact pour le module mk2Wifi et Home Assistant (9600 bauds, 7E1)

  • JSON : Format JSON pour intégration domotique

Important

Avec le module mk2Wifi, repassez en mode IoT après les premiers tests, puis recompilez et téléversez : le module ne comprend que ce mode.

Sonde 2 (CT2) et Afficheur

La sonde CT2 mesure l’énergie routée : faire passer par elle les fils de toutes les sorties locales (triacs et relais). Si aucune sonde n’est montée :

inline constexpr bool DIVERTED_CT_PRESENT{ false };

L’afficheur se règle avec TYPE_OF_DISPLAY :

  • NONE : Pas d’affichage

  • SEG : Afficheur 7 segments (carte OLD_SEG)

  • SEG_HW : Afficheur 7 segments avec ses circuits d’économie de broches

  • OLED : Afficheur OLED (cartes OLD_OLED et NEW)

Configuration des Sorties Triac

Définir le nombre de sorties et la broche de chacune :

// Exemple : 2 sorties triac
inline constexpr uint8_t NO_OF_DUMPLOADS{ 2 };

inline constexpr uint8_t physicalLoadPin[NO_OF_DUMPLOADS]{
  Load::local(5),  // Sortie 1 sur la broche D5
  Load::local(6)   // Sortie 2 sur la broche D6
};

Note

Le config.h fourni a une seule sortie, un triac sur D5. Pour en ajouter, changer ensemble NO_OF_DUMPLOADS, physicalLoadPin et loadPrioritiesAtStartup. Une charge pilotée par radio par une unité distante s’écrit Load::remote(1) (unité 1, de 1 à 3) au lieu de Load::local(…).

Ordre de Démarrage

Définir la priorité des charges :

inline constexpr uint8_t loadPrioritiesAtStartup[NO_OF_DUMPLOADS]{ 0, 1 };

Signification : les priorités désignent les sorties par leur rang dans physicalLoadPin, à partir de 0 : { 0, 1 } démarre d’abord la sortie 1 (D5), puis la sortie 2 (D6).

Relais, Sondes de Température, Double Tarif, Radio (Optionnel)

Ces fonctions s’activent chacune par un réglage de config.h, puis se détaillent dans config.h, dans la section de chaque fonction :

  • Relais (RELAY_DIVERSION, relays) : relais tout-ou-rien pilotés par le surplus.

  • Sondes de température (TEMP_SENSOR_PRESENT, temperatureSensing) : sondes DS18B20, dont il faut indiquer les adresses (le mode étalonnage les liste au démarrage). Collez une étiquette avec l’adresse sur le câble de chaque sonde.

  • Double tarif (DUAL_TARIFF, dualTariffPin, scheduledBoosts, iTemperatureThreshold) : heures creuses et boosts programmés, avec un seuil de température.

  • Radio (RF_LOGGING_PRESENT, config_rf.h) : journalisation et charges distantes par module RFM69.

Configuration dans calibration.h

Ce fichier contient les paramètres d’étalonnage, avec un jeu de valeurs par carte-mère : le routeur utilise celui de PCB_VERSION.

// Anciennes cartes
inline constexpr float f_powerCalOldBoard{ 0.05000F };
inline constexpr float f_powerCalDivertedOldBoard{ 0.05000F };
inline constexpr float f_voltageCalOldBoard{ 0.805653F };
// Carte universelle
inline constexpr float f_ctRating{ 50.0F };
inline constexpr float f_ctRatingDiverted{ 50.0F };
inline constexpr float f_powerCalPerAmp{ 0.00286405F };
inline constexpr float f_voltageCalNewBoard{ 0.888065256F };

Carte universelle : f_ctRating et f_ctRatingDiverted sont les calibres (courant nominal) des sondes CT1 et CT2, en ampères. Si vos sondes ne sont pas des 50 A / 333 mV, indiquez dès maintenant leur calibre : avec une sonde à sortie courant et une résistance de charge R (par exemple YHDC SCT-013-000), le calibre vaut 666 / R, soit 30,3 avec 22 Ω.

Avertissement

Ne modifiez PAS les autres valeurs maintenant — elles seront déterminées lors de l’étalonnage (voir chapitre Étalonnage — Monophasé).

Les paramètres par défaut permettent de tester le routeur.

Étape 3 : Connexion et Programmation

Préparation

Note

L’adaptateur FTDI ne peut PAS alimenter le routeur seul !

Le routeur doit être alimenté par sa propre alimentation 230 V.

Connexion du Routeur

Le kit est livré avec un adaptateur FTDI : une petite carte avec un connecteur USB d’un côté et 6 broches mâles de l’autre. Ces 6 broches ont le même ordre que le connecteur FTDI (J0) de la carte-mère : chaque broche de l’adaptateur se relie à la broche de même rang du connecteur, sans croisement.

  1. ⚠️ Couper l’alimentation secteur du routeur (disjoncteur)

  2. Brancher l’adaptateur FTDI sur le connecteur FTDI (J0) du routeur. La broche 1 (GND) est marquée « GND> » sur la sérigraphie.

    Broche de l’adaptateur

    Connecteur FTDI (J0) de la carte

    GND

    Broche 1 : GND

    CTS

    Broche 2 : non connectée

    VCC

    Broche 3 : non connectée

    TX (émission)

    Broche 4 : RX de l’ATmega328P

    RX (réception)

    Broche 5 : TX de l’ATmega328P

    DTR

    Broche 6 : DTR, reset automatique

    Avertissement

    ⚠️ Vérifiez que GND de l’adaptateur arrive bien sur la broche 1 (« GND> ») : branché à l’envers, l’adaptateur ne communique pas. La liaison DTR est indispensable : sans elle, l’ATmega328P n’est pas redémarré automatiquement pour le téléversement, qui échoue (« not in sync »).

    La broche 3 (VCC) du connecteur n’est reliée à rien sur la carte : le routeur n’est jamais alimenté par l’adaptateur, il reste alimenté par le secteur.

  3. Vérifier le cavalier ou le commutateur de l’adaptateur FTDI : sa tension doit être celle de l’ATmega328P. Sur la carte universelle, c’est 3,3 V (position d’usine du cavalier V sel., voir Configuration des cavaliers) ; 5 V seulement si ce cavalier a été passé en 5 V.

  4. Connecter l’adaptateur FTDI à l’ordinateur (port USB)

  5. Mettre le routeur sous tension (réenclencher le disjoncteur)

Configuration Arduino IDE

  1. Menu : Outils → Type de carte → Arduino AVR Boards → Arduino Uno

  2. Menu : Outils → Port → COMx (Windows), /dev/tty.usbserial-xxx (macOS) ou /dev/ttyUSB0 (Linux)

    • Choisir le port correspondant à l’adaptateur FTDI

    • Si plusieurs ports : essayer chacun jusqu’à ce que ça fonctionne

Compilation et Téléversement

Checklist avant téléversement

  • [ ] Modifications sauvegardées dans config.h

  • [ ] Routeur alimenté (230 V)

  • [ ] Adaptateur FTDI connecté (USB + PCB)

  • [ ] Bon port COM sélectionné

  • [ ] Type de carte = Arduino Uno

  • [ ] ATmega328P du kit en place : il est livré avec son bootloader, il n’y a qu’à téléverser le firmware (une puce vierge achetée ailleurs devrait d’abord recevoir le bootloader Arduino Uno avec un programmateur ISP)

  1. Cliquer sur le bouton « Vérifier » (✓) pour compiler

    • Attendre la compilation (1–2 minutes la première fois)

    • Vérifier qu’il n’y a aucune erreur

  2. Si la compilation réussit, cliquer sur « Téléverser » (→)

    • Les LED TX et RX de l’adaptateur FTDI clignotent (si l’adaptateur en a)

    • Attendre le message « Téléversement terminé »

Astuce

Si la compilation échoue avec le message Please define 'gnu++17' in 'platform.txt', c’est que le fichier platform.txt n’a pas été correctement modifié (voir Configuration Arduino IDE pour C++17).

Résolution des Problèmes

Erreur : avrdude: stk500_recv(): programmer is not responding

Causes possibles :

  1. Mauvais port COM sélectionné → Essayer un autre port

  2. Routeur non alimenté → Vérifier l’alimentation 230 V

  3. Câblage FTDI incorrect → Vérifier TX ↔ RX inversés

  4. ATmega328P mal inséré → Vérifier l’orientation et l’insertion complète

  5. Fil DTR non câblé (avec des fils séparés) → pas de reset automatique : câbler la broche 6 (DTR)

  6. ATmega328P de remplacement, acheté vierge (sans bootloader) → y graver le bootloader Arduino Uno avec un programmateur ISP ; la puce du kit en a déjà un

  7. Cavalier 3,3 V/5 V de l’adaptateur mal placé → voir Connexion du Routeur plus haut

Erreur : static assertion failed: **** Please define 'gnu++17' in 'platform.txt' ! ****

Le fichier platform.txt n’a pas été modifié correctement : le compilateur ne travaille pas en C++17. D’autres erreurs suivent ce message ; elles disparaissent avec la bonne modification.

Solution : Reprendre Configuration Arduino IDE pour C++17.

Port COM n’apparaît pas

  1. Vérifier que les pilotes FTDI sont installés (Installation Pilotes FTDI)

  2. Débrancher/rebrancher l’adaptateur FTDI

  3. Redémarrer l’ordinateur

Ouverture du Moniteur Série

  1. Menu : Outils → Moniteur série

  2. Configurer en bas à droite :

    • Vitesse (baud rate) : 9600

    • Fin de ligne : sans importance (le routeur ne lit rien sur le port série)

Messages Attendus

L’ouverture du moniteur série redémarre le routeur (signal DTR). Après 3 secondes, il affiche sa configuration, terminée par —-, puis une ligne de mesures toutes les 5 secondes (valeur par défaut de DATALOG_PERIOD_IN_SECONDS, dans config_system.h).

Exemple en triphasé, avec la sortie HumanReadable (extrait d’une capture réelle, lignes omises remplacées par « … ») :

Le contenu de la configuration dépend de config.h et de calibration.h. Dans les lignes de mesures, P est la puissance totale en W (positive en import), P1 à P3 celle de chaque phase et V1 à V3 les tensions. En monophasé, la ligne donne P: et V:, puis, avec la sonde CT2, la puissance et l’énergie routées : diverted <W> W, <Wh> Wh.

Note

Avec le config.h fourni (SERIAL_OUTPUT_TYPE en IoT), la configuration s’affiche de la même façon, à 9600 bauds 8N1, puis le routeur passe en 7E1 pour le module mk2Wifi : les caractères illisibles qui suivent sont normaux. Pour lire les mesures au moniteur série, passer en HumanReadable (voir Format de Sortie Série plus haut).

Si Aucun Message n’Apparaît

  1. Vérifier que le bon baud rate est sélectionné (9600 bauds)

  2. Vérifier le câblage FTDI (TX ↔ RX)

  3. Vérifier que le routeur est alimenté

  4. Vérifier l’oscillateur 16 MHz et les condensateurs C7/C8

Adresses des Sondes de Température

Le routeur ne recherche pas les sondes : il lit celles dont les adresses sont dans config.h. En mode étalonnage (CALIBRATION_MODE à true, avec TEMP_SENSOR_PRESENT), il les liste au démarrage sur le moniteur série, avec la sortie lisible. Sinon, pour relever les adresses, téléverser l’exemple de la bibliothèque OneWire (Fichier → Exemples → OneWire → DS18x20_Temperature), en changeant au besoin la broche dans OneWire ds(…). Le moniteur série affiche alors l’adresse de chaque sonde branchée :

ROM = 28 AA BB CC DD EE FF 1
ROM = 28 AA BB CC DD EE FF 2

Copier ces adresses dans config.h (section sondes de température, chaque octet sous la forme 0x28, 0xAA…, un octet affiché 1 s’écrit 0x01), puis téléverser à nouveau le firmware du routeur. Coller une étiquette avec l’adresse sur le câble de chaque sonde.

Test de la partie mesures

Le transformateur ZMPT101K (TR1) fournit le signal de mesure de tension CA.
Cela peut être vérifié en exécutant un programme (croquis) qui affiche les mesures analogiques prises par le processeur Atmel (IC1).

Le programme est RawSamplesTool_2chan.ino : il se trouve dans le dossier dev/RawSamplesTool_2chan/ du dépôt PVRouter-1-phase et se téléverse seul, sans le firmware du routeur.

Note

Le programme lit la tension sur A3, CT1 sur A5 et CT2 sur A4, les entrées de la carte Mk2 de Robin Emley (OLD_SEG). Sur les autres cartes (tension A0, CT1 A1, CT2 A3), changer les trois numéros de broche en tête du programme.

Après avoir téléversé ce croquis sur le processeur via l’Arduino IDE, la fenêtre série (icône en forme de loupe) doit être ouverte.
Après avoir terminé chaque exécution, le programme peut être redémarré à partir du clavier en saisissant le caractère « g », suivi de Entrée.
Le programme RawSamplesTool_2chan affiche les échantillons de tension alternative et de courant pour un ou plusieurs cycles secteur complets.
Si un courant important est mesuré ainsi que la tension, les résultats affichés sembleront plus intéressants.
Si aucun signal n’est disponible sur les ports CT1 et CT2, les formes d’onde de ces canaux seront toutes deux des lignes droites.
Seul le signal de tension affichera un aspect sinusoïdal.
Pour vérifier le fonctionnement des ports CT1 et CT2 pendant que le PCB est testé sur le banc, un câblage adapté sera nécessaire.

Prochaines Étapes

✅ Le firmware est maintenant installé et fonctionnel !

Prochaines étapes :

  1. Étalonnage : Voir chapitre Étalonnage — Monophasé

    L’étalonnage est recommandé : il donne des valeurs réalistes, et il devient nécessaire dès que des relais routent le surplus, car leurs seuils sont en watts.

  2. Installation finale : Connexion au réseau électrique (faire appel à un électricien qualifié)

  3. Configuration avancée : Relais, sondes de température, double tarif, etc., avec le configurateur

Avertissement

Ne pas connecter le routeur au réseau électrique domestique avant d’avoir :

  • [ ] Vérifié toutes les soudures (pas de pont, pas de soudure froide)

  • [ ] Lu le chapitre de sécurité

  • [ ] Fait appel à un électricien qualifié (fortement recommandé)

Important

FONCTIONNALITÉ : L’étalonnage se fait après l’installation électrique. Le routeur peut être connecté sans étalonnage (pas de danger), mais ses mesures seront approximatives.
